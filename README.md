# OKX 포지션 → 텔레그램 토픽 자동 연동

## 준비물
- GitHub 계정 (레포지토리는 **반드시 Private**로 생성 — 포지션 정보가 담긴 state.json이 커밋되기 때문)
- OKX API 키 — **반드시 "읽기 전용(조회)" 권한만** 부여, 출금/거래 권한은 절대 켜지 말 것
- 텔레그램 봇 토큰 (@BotFather 에서 발급)
- "토픽(포럼)" 기능이 켜진 텔레그램 그룹, 그리고 해당 그룹의 특정 토픽 ID

## 1. 저장소 준비
1. GitHub에 **Private** 저장소 생성
2. 이 폴더의 `okx_telegram_bot.py` 와 `.github/workflows/okx_telegram_tracker.yml` 을 그대로 업로드

## 2. OKX API 키 발급
1. OKX 로그인 → 우측 상단 프로필 아이콘 → **API** (또는 "API Key") 메뉴로 이동
2. **Create API Key** (V5) 클릭
3. **API 이름(Label)**: 식별 가능한 아무 이름 입력 (예: `telegram-tracker`)
4. **Passphrase**: 여기서 직접 정하는 별도의 문자열 (계정 비밀번호와 다름). API 요청 시마다 필요하므로 반드시 기록해둘 것
5. **Permissions(권한)**: **"조회(Read)"만 체크된 상태로 유지**하고, **"거래(Trade)"·"출금(Withdraw)"는 반드시 체크 해제**
   — 이 프로젝트는 계좌 조회만 하면 되므로 그 외 권한은 필요 없고, 켜두면 키 유출 시 위험만 커짐
6. **IP 주소 제한(선택)**: GitHub Actions는 실행마다 서버 IP가 바뀌는 구조라, 특정 IP 몇 개만 등록하는 화이트리스트 방식은 이 조합과는 잘 안 맞습니다. 비워두는 대신, 5번의 "조회 전용" 권한으로 리스크를 낮추는 방식을 권장 (자체 고정 IP 서버에서 돌릴 계획이라면 그때 IP 제한을 추가하면 됩니다)
7. 2단계 인증(OTP/이메일/SMS 등) 입력 후 확인
8. 생성 완료 시 **API Key / Secret Key / Passphrase**가 표시됩니다. **Secret Key는 이 화면에서 딱 한 번만 보여지고 이후 재조회가 불가능**하므로, 그 자리에서 바로 안전한 곳(비밀번호 관리자 등)에 복사해둘 것

발급 자체는 무료입니다. 다만 실계좌 키를 바로 쓰기보다, 먼저 **데모 트레이딩(모의투자)** 환경에서 별도로 키를 발급해 충분히 검증하는 것을 권장합니다. 데모 환경은 실거래 환경과 완전히 분리되어 있어 API 키도 따로 발급해야 하고, 선물거래 활성화 여부도 각각 따로 켜야 합니다. 데모 API 키를 쓰는 경우 아래 4번의 GitHub Variables에서 `OKX_SIMULATED`를 `1`로 설정하세요.

## 3. 텔레그램 봇 & 토픽 설정
1. 텔레그램에서 `@BotFather` 에게 `/newbot` 으로 새 봇 생성 → 토큰 확보
2. 대상 그룹 설정에서 **"주제(Topics)"** 기능을 켜서 포럼 모드로 전환
3. 봇을 그룹에 **관리자로 추가** (메시지 전송, 메시지 고정 권한 필요)
4. 원하는 토픽을 열어 아무 메시지나 보낸 뒤, 그 메시지의 링크를 복사하면
   `https://t.me/c/1234567890/8` 형태로 나옵니다.
   - `1234567890` → 그룹 채팅 ID (실제 사용 시 앞에 `-100`을 붙여 `-1001234567890` 형태로 사용)
   - `8` → 토픽 ID (`TELEGRAM_TOPIC_ID`)
5. 채팅 ID를 잘 모르겠다면 봇을 그룹에 넣은 뒤 아무 메시지나 보내고,
   `https://api.telegram.org/bot<토큰>/getUpdates` 를 브라우저로 열어 `chat.id` 값을 확인해도 됩니다.

## 4. GitHub Secrets / Variables 등록
저장소의 Settings → Secrets and variables → Actions 에서 등록:

**Secrets (필수, 비공개)**
- `OKX_API_KEY`
- `OKX_API_SECRET`
- `OKX_API_PASSPHRASE`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID` (예: `-1001234567890`)
- `TELEGRAM_TOPIC_ID` (예: `8`)

**Variables (선택)**
- `OKX_SIMULATED` — 데모 트레이딩이면 `1`, 실계좌면 생략(기본 `0`)
- `OKX_INST_TYPES` — 감시할 상품 종류, 기본 `SWAP` (콤마로 여러 개 지정 가능, 예: `SWAP,FUTURES`)

## 5. 실행
1. GitHub 저장소의 Actions 탭에서 워크플로우를 확인
2. 처음에는 `workflow_dispatch`(수동 실행) 버튼으로 1회 실행해 정상 동작 확인
   - 첫 실행은 "베이스라인 저장" 모드로 동작합니다 — 이미 보유 중인 포지션을
     "신규 진입"으로 잘못 알리지 않고, 조용히 현재 상태만 저장한 뒤 요약 메시지만 고정합니다.
3. 이후로는 5분마다 자동 실행되며, 포지션 변화가 감지될 때만 이벤트 메시지가 올라옵니다.

## 확인해야 할 점
- 첫 실행 후 텔레그램 토픽 상단에 "현재 보유 포지션" 메시지가 고정(pin)되어 있는지 확인
- 실제 매매 후 몇 분 내로 신규진입/추가매수/부분청산 메시지가 올바르게 분류되는지 확인
- `전체청산` 메시지에 실현손익이 비어 있다면(정산 데이터 반영 지연), 다음 실행에서는
  정상적으로 채워지는지 확인 (거래소 쪽 정산 기록 반영에 약간의 지연이 있을 수 있음)
